# Portfolio design

The portfolio should make the work easy to assess. Its visual identity comes
from the portrait, actual outputs, writing and choice of projects.

## Reading order

- A short introduction and the existing NC portrait
- Selected work with genuine screenshots or figures
- A compact index for smaller personal tools
- Writing and the original analyses

The header contains Projects, Writing and Tools. The system overview is a
secondary route. Existing public tools remain available without filling the
main navigation with individual utilities.

## Visual choices

- Source Serif 4 for names and page titles
- Source Sans 3 for body text, navigation and project titles
- Near-white background, dark text, a restrained green link colour and fine rules
- A shared page grid and a narrower reading column
- Original image proportions, useful alternative text and full-size figures
- Visible keyboard focus and layouts that work at narrow widths

These are choices for this portfolio, not a universal recipe. Test them with
the actual content. A card, diagram or accent colour is useful when it helps
the reader understand a real relationship.

## Project writing

Describe what exists, what the work involved and any decision worth explaining.
Use a structure appropriate to the project. Avoid adding the same set of
headings to every tool.

Keep collaboration and third-party tools clear. Do not invent user counts,
time savings, reliability figures or investment performance. Distinguish
dated publications, exploratory coursework and live tools.

## Evidence and examples

Use actual interfaces, reports or notebook figures when they show the work.
Small scripts can have text-only entries. A repeated decorative workflow image
should not be the default project cover.

Interactive examples are secondary to the explanation of the real project.
They remain visibly labelled as fictional examples, and do not perform real
bookings, send messages or call models.

## Before publishing

Check the rendered homepage, project list, a case page, the notebook and the
retained tools. Verify navigation, image loading, downloads, demo behaviour,
keyboard focus, narrow screens and contrast. Keep before/after evidence and
record anything not verified.
